# 项目分类与科学版本管理实施计划

## 目标与授权范围

按用户要求直接整理现有工作区并建立本地 Git 科学实验管理；不修改原始采样、不重算历史结论、不推送远程、不新增RF采集。

## 已确定的目录方案

- `data/raw`：原WAV及复现实验需要的只读外部输入快照。
- `data/derived`：CI16导出和原始候选周期切片。
- `references`：公开模板、第三方参考实现、许可和实际使用的VI资源。
- `experiments/E001..E007`：按研究问题分组，每组独立的`scripts/results/figures`及实验记录。
- `reports/E001..E007`：历史中文报告原文，不重写旧结论和溯源路径。
- `learning`：公式库、Notebook和教学算例。
- `provenance`：基线哈希、原路径到新路径映射和外部输入来源。
- `docs`：当前状态、复现方式与实验规范。
- `tools/tests/.githooks`：受验证的执行入口和版本提交检查。

采用显式的旧产物路径索引兼容历史脚本；只改I/O路径和执行上下文，不改变估计公式。实验执行器将输出隔离到`runs`，避免覆写已封存结果。原始数据及大型数值文件由Git LFS保存。

## 三个可验证提交

1. `0.0.1`：导入前基线，逐文件验证Git或LFS中的字节与原文件相同，创建不可覆盖版本标签。
2. `0.0.2`：分类迁移、输入快照、路径兼容、隔离执行、实验索引。校验所有保留证据哈希、Python语法、内部依赖、候选切片与关键数值正对照。
3. `0.0.3`：提交守卫、版本准备工具和测试。拒绝缺VERSION/CHANGELOG、跳号、记录不完整或提交标题错误；验证合法提交路径。

每次提交记录Purpose、Changes、Scientific record、Validation、Limitations，版本严格从当前HEAD的末位加一。使用本机已有提交身份，不修改全局Git设置。

## 验证边界

目录迁移不会使早期科学假设升级为已验证消息。历史报告中的绝对路径作为溯源保留，当前入口以README和项目索引为准。需要完整外部档案的历史清点/轨道候选审计明确标为外部依赖，不伪造其可独立重跑能力。
