# 科学实验与 Git 提交规范

版本由 `VERSION` 唯一决定，从 `0.0.0` 起每次提交只允许最小位加 1：`0.0.1 → 0.0.2 → 0.0.3`。文档、数据、修复和失败实验记录的提交均适用，不允许跳号或复用版本。

每次提交同时更新 `VERSION` 与 `CHANGELOG.md`。最新 changelog 必须匹配版本、日期，并包含有实质内容的五段：

1. **Purpose**：本次要解决的明确问题或假设。
2. **Changes**：代码、数据和记录实际变化。
3. **Scientific record**：输入/参数/种子/对照/结果，或明确不改变科学结论。
4. **Validation**：实际执行的命令与结果；失败和未执行项如实写明。
5. **Limitations**：证据边界、依赖和仍未验证的部分。

提交主题必须以 `v<版本>: ` 开头。验证通过后提交并创建同版本注释标签；不得改写已提交的历史，不使用 `--no-verify`。不因负结果而删除证据。

`0.0.1` 是整理前基线，`0.0.2` 是分类与路径迁移；`0.0.3` 引入本地自动守卫及安装入口。自动守卫检查暂存区而非仅检查工作区，确保漏加版本/日志、跳号、章节缺失和主题不匹配会被拒绝。自动格式检查不能证明实验已经执行，提交者仍须记录真实验证。

新克隆须安装本地钩子；Git 不会自动启用仓库内的钩子目录。Git LFS 钩子须一并保留。远端推送、发布与修改历史均需另行授权。

## 实际操作

首次检出运行 `python tools/install_hooks.py`，将本仓库的 `core.hooksPath` 设为 `.githooks`；不修改全局 Git 配置。此目录同时提供 LFS 的 pre-push、post-checkout、post-merge、post-commit 钩子。

完成一个可验证改动后：

1. 执行相关验证，记录结果与未覆盖范围。
2. 运行 `python tools/release.py --help`，使用 `--title`、`--purpose`、`--changes`、`--scientific-record`、`--validation`、`--limitations` 准备记录。每个内容参数可重复；日期默认北京时间，可显式指定 `--date YYYY-MM-DD`。
3. 工具从 HEAD 计算唯一下一补丁版本，同时写入 VERSION/changelog；不暂存、不提交。已有待提交版本时拒绝再次准备。
4. 审阅差异，执行 `git add --all` 和 `python tools/verify_project.py --staged`。用 `git diff --cached --check` 检查新增文本。
5. 执行 `git commit -m "v<版本>: <具体变化>"`；两个守卫从索引读取版本/记录，并保留既有 changelog 历史。提交后使用 `git tag -a v<版本> -m "<验证摘要>"` 创建注释标签。

自动检查拒绝漏暂存、版本复用/跳号、无效日期、缺失/重复/空章节、占位内容、改写旧日志或主题版本不匹配。它检查结构与最小内容要求，不能判定自然语言是否真实；科学记录仍需审阅。钩子是本地防误操作机制，克隆后未安装或刻意绕过钩子会失去拦截，因此仓库规则明确禁止绕过。
