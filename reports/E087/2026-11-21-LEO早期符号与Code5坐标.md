# LEO 早期符号与 Code 5 的坐标关系

LEO Tracker 在上边缘第 4 个 OFDM 符号导出了 24 个稳定符号，并用同一组位置比较 DS7 与 UT。这里从位置起算，以主项目 E014 的宽带码字及 E036 的 CRC 验证头部给 UT 端的符号确定资源归属。[LEO 原工程](https://github.com/misko/leo-tracker-reduxredux/blob/main/reports/2026_09_27_ds7_header/DATA_RECOVERY.md) · [Liu 等的 H1 分配与 Code 5](https://arxiv.org/html/2610.29387v2#S4)

## 资源坐标和逐位复现

源位置为载波 476–487、496–507。按物理频率排序并跳过导频和未加载载波，槽内零基序号是 976–999。全帧从 OFDM 符号 2 起算，资源号为 $r=1004(s-2)+q$，所以第 4 个符号的这组位置对应 $r=2984,\ldots,3007$。冻结宽带布局的 H1 结束于资源 227，第一组 Code 5 从 228 起，每字 2048 位。第二个字始于 2276，所测位置对应零基系统位 708–731。

UT 两个前端使用同一份原始 IQ 和相同 Qin 参考模板，输入 SHA-256 匹配。原工程七帧导出的 24 位字样一致。对 E014 中有完整第二字的 10 个候选，从原始硬判系统位乘冻结生成矩阵，全部 10,240 个校验位逐位等于实收硬判。然后将这 24 个 Code 5 系统位用解析 PN 与 Qin 经验参考的实际复比值变换至原工程坐标。统一取反后每个候选都复现其字样。固定其他设置只移码字索引 $-2,-1,+1,+2$，即使分别允许最佳整体符号，仍分别差 10、12、11、11 位。原工程使用盲 BPSK 轴，整体反号符合其极性歧义。此处两套前端共享录波，能够核对解调和资源映射。

## 档案对照及证据边界

E036 的全部 1,009 对 CRC 有效头部的 H2 均从资源 4324 或更后开始，所测资源位于第一段 Code 5。对其中有本地硬星座快照的 117 帧，只在这 24 个固定坐标用 Qin 参考计算符号。116 帧具有完整实轴判决，另 1 帧保留为不可判。28 帧与 UT 字样在整体极性下相同。DS7 字样在这批档案中没有精确匹配，最小汉明距 4，出现在帧 1 和帧 3。这些都是现成的档案段，比较不使用拟合参数或随机划分。

对 UT 录波，所测字样属于信道码系统区，可以跨帧稳定。DS7 仅有双接收机汇总位与已验导频，尚缺该访次独立通过 CRC 的 H1/H2 或完整 Code 5 字。其 24 位与 UT 的差异不足以确认字段语义、时间、卫星编号或同一分配模式。[E014](../../experiments/E014/README.md) · [E036](../../experiments/E036/README.md) · [E087 两次运行](../../experiments/E087/README.md)
