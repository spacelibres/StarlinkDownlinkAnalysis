# 从 LEO DS9 双路判决复验 H1 的局部卷积码

LEO 原工程已从现有窄带缓存导出 OFDM 第 2–7 个符号的双接收机硬判。在 DS9 两个下边缘访次，第 2 个 OFDM 符号的 24 根非导频载波落在 H1 卷积码编码位置 4–27。该段只依赖头部的前 10 个信息位，因此可在已有位回执上检验局部 H1 译码。既有 E129 三位异或则落在 Code 5 区，使用另一组资源。[LEO 原工程](https://github.com/misko/leo-tracker-reduxredux/blob/main/reports/2026_09_28_sequence_semantics/LOCAL_HEADER_RECOVERY.md) · [Liu 等的 H1 卷积码](https://arxiv.org/abs/2610.29387v2) · [E129](../../experiments/E129/README.md)

## 位判决和对照

沿用 E135 的秦氏模板到 PN 相位约定，把信息位经卷积码编码，投影到实际载波，再转换为原工程的模板相对实部符号。设输入为 $u$、全局极性为 $a$，在可判坐标 $J$ 上最小化 $\sum_{j\in J}[y_j\ne (G_Ju\oplus b_J\oplus a)_j]$。其中 $b_J$ 只有模板相位给定。候选空间包含全部 1,024 个 10 位输入及两个极性，同距结果全部保留，只在所有最优候选一致时输出某一位。在完整 24 位上，投影秩为 10，加入一个独立极性自由度后仍有 13 条约束；最小距离为 1。公开 `0x3048` 的前 10 位 `0011000001` 只在预测后用于比较。循环错位只搬动 24 个编码位置对应的矩阵行，实收位、相位模板和搜索规模保持相同。[相位约定](../../experiments/E135/README.md) · [E058 头部复验](../../experiments/E058/README.md)

原掩码最初用于找随帧变化的符号，仅保留 22、57 个 H1 观测。直接使用每帧双路同号判决并擦除分歧后，两个访次分别保留 435、422 个编码判决。公开前缀在 44／46 帧的最优集合内，其中 28 帧唯一吻合。逐位输出中，424 位吻合、2 位不符、34 位擦除。两个唯一不符帧都在 DS9-last，判为 `0011000000`。所有帧的双路同号分支都选中整体反相，未使用公开前缀校正极性。[逐帧判决与错位对照](../../runs/v142-leo-projected-h1/artifacts/experiments/E144/results/leo_projected_h1.json)

23 种循环错位未产生任何包含公开前缀的最优集合。主分支两个访次的最小失配总数为 9、14，错位 3 个坐标时为 9、15。因此距离本身对相邻的卷积时间移位区分很弱，固定资源映射和事后参考都有价值。两个访次来自同批 DS9 历史语料，实收证据是硬判回执。完整的 H1 两块信息、描述符、CRC 和身份没有达到验证条件。两次结果字节一致，SHA-256 为 `4ff4f52eebc5831aa0ff25147abceb1fc66b880432d9ed2dad6ca01e8e404c00`。[首次运行](../../runs/v142-leo-projected-h1/manifest.json) · [复跑](../../runs/v142-leo-projected-h1-confirm/manifest.json)

## 同一资料的 Code 5 观测范围

对 12 个导出条目清点，7 个有实收硬判帧。假定沿用宽带已验证的初始 Code 5 分配与生成矩阵，在这 7 个条目覆盖的前三个字中，21 个局部矩阵的行秩都等于可见坐标数（每字 16、24 或 48）。等价地，任意这些可见位的赋值都可补成合法完整码字。原工程早期符号的相关性仍可能来自字段内容、调制或共同相位，但在这组掩码上无法单独用已知 Code 5 码验算。此前 E136 的目录与首记录跨度关系也需要对应布局和载波。[E136](../../experiments/E136/README.md)
