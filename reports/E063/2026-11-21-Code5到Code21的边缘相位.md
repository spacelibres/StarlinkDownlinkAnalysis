# 用前段 Code 5 校准后段 Code 21 的边缘相位

在 Qin 的软符号档案中，用同帧前段 Code 5 的实测信号估计子载波 +511 的连续相位。后段走两条固定接收前端，按实际码字位置去重后，58 个保留位置有 43 个通过全部 3,072 个接收校验位。43 个包含 E062 的全部 16 个位置，并增加 27 个。分别擦除和重建 +511 后，得到同一组通过位置和相同位串。[E062](../E062/2026-11-21-Code21留出校验与单符号纠正.md)

## 观测与检验

复用 E034 的帧和 H2 资源坐标、E012–E013 的 Code 5 矩阵、E016 的 Code 21 矩阵。固定 Code 21 位序和极性，排除用于选择这套约定的第 991 帧。另 11 帧中的 58 个位置用于评估。直接和导频前端来自同一捕获。Qin 记载了远端频谱边缘相位噪声较大的现象，Liu 的论文给出 Code 21 的编码布局。E038 已检验同帧 Code 5 到后段另一格式的边缘相位转移，E062 定位了这批 Code 21 的三个 +511 错位。[Qin 等 §VIII-B](https://arxiv.org/html/2602.02627#S8.SS2) · [Liu 等 §VI-E](https://arxiv.org/html/2610.29387v2#S6.SS5) · [E038](../../experiments/E038/README.md)

对 Code 5 先擦除六个边缘载波。每个保留帧在两路都用其余实测位唯一补全，逐路 58/58 字。对目标载波的复观测乘以补全极性后求和，估计响应 `Σ yᵢ(1−2bᵢ)`，取负相角修正后段 +511。拟合要求至少三个参考点、幅度加权相位集中度至少 0.6。对 Code 5 留一字验证时，直接前端的目标载波实部符号差异从 87/116 降至 0/116，导频前端从 5/116 降至 0/116。其余 Code 21 载波保持原判。错帧对照固定使用下一个保留帧，最后一个帧使用第一个帧。

| 后段检验 | 直接前端 | 导频前端 | 去重位置 |
|---|---:|---:|---:|
| 保持原判 | 5 | 6 | 11 |
| 同帧 +511 四分之一圈 | 28 | 8 | 32 |
| 同帧 +511 连续相位 | 42 | 14 | 43 |
| 错帧 +511 连续相位 | 1 | 3 | 4 |
| 用 +510 的四分之一圈修正 +511 | 5 | 6 | 11 |
| +511 四分之一圈修正增加半圈 | 0 | 0 | 0 |
| 擦除 +511 | 42 | 14 | 43 |
| 擦除 +510 | 5 | 7 | 12 |
| 擦除 −512 | 5 | 6 | 11 |

擦除计算沿用 E062 的三个分散校验划分。每次先用训练侧的实测校验位唯一解出被擦除的系统位，再逐位比对留出侧。两侧对未知位均满秩，三次解必须逐位一致。通过的 +511 擦除字有 2–4 个校验位也在该载波上，对这几个位置只保留重编码补全。连续相位路径仍使用全部接收校验位。报告里的两个结果共享同一套采样和编码模型。

## 复算与跨录波适用性

两次完整复跑的 JSON 指纹为 `38ffdb7ed147aafd16c197ebf92bcc8deb8bd378b214ea6da357de65e5acfdff`，NPZ 指纹为 `dc6417c0bd0387e2971b1031e11b45de8a5c42db0e57b669f42a2b52f4e8b656`。另将 NPZ 的 167 个记录以大端位序解包，用 E016 的稠密矩阵直接计算 `(bits[:5120] @ P) % 2`，全部与剩余 3,072 位吻合。167 个记录来自 48 个位置，其中 43 个为保留位置。两前端和两种方法在重叠位置的位串一致，E062 重叠的 16 个保留位置也逐位一致。NPZ 使用 `phase_` 和 `word_` 标记相位转移和擦除重建，后者的未观测校验坐标在 JSON 中。

用 LEO 两份 selection JSON 中的调谐边缘和冻结频偏核对坐标。10 个唯一短窗均调到下边缘，中心为未移位 FFT 载波 531.5。对 +511 计算 `(511−531.5) × 234375 + CFO`，相对采样中心的频率为 −5.019 至 −4.334 MHz。其绝对值超过 2.5 MS/s 的 ±1.25 MHz 观测窗。这些 IQ 能复验下边缘时频模型，当前 +511 的跨接收机复验仍缺覆盖该频率的另一次捕获。现有证据无法决定相位异常来自空口、接收硬件还是档案处理，也未确认业务字段语义。[LEO 原工程导频索引](https://github.com/misko/leo-tracker-reduxredux/blob/main/docs/concepts/starlink-transmissions.md) · [本地 LEO 元数据指纹](../../provenance/leo_input_snapshot.json)
