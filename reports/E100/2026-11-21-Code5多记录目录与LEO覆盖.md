# Code 5 多记录目录、零填充与 LEO 覆盖

Code 5 内部目录可以给出整个首分配中每一条记录的字节范围。两种记录描述项交替出现，目录结尾还单独编码了末尾零填充的长度。在 1,009 个 Qin 档案帧和两份宽带重放的 28 帧中，目录、各条记录及填充的字节数相加，均精确等于外层 H1 给出的 Code 5 容量。[数值记录](../../runs/v098-code5-records-final/artifacts/experiments/E100/results/code5_directory_records.json)

Liu 等的论文建立了外层 H1 的 MCS 项与码字分配的关系，Qin 等提供边缘导频与实测频域参考。E091 验证了内层目录 CRC24 和首条记录终点。E100 扩展到目录里所有描述项，并用已经冻结的 H1 和实际读取的填充独立检验终点。[Liu 等第 IV 节](https://arxiv.org/html/2610.29387v2#S4) · [作者代码和数据](https://github.com/misaka666/Starlink-Downlink-Analysis) · [Qin 等导频研究](https://arxiv.org/abs/2602.02627) · [E091](../../experiments/E091/README.md)

## 目录字段

开头两个字节为目录总长度 $L$ 和 `00`，最后三个字节是 E091 的 CRC24。记录描述项按下表交替。这里的 `u16le` 表示两个字节按小端无符号整数读取。

| 字节前缀 | 后续字节与读法 |
|---|---|
| `01 f0 0f` | 后两字节的 `u16le >> 4` 为记录长度，低四位为 `6` |
| `10 00 ff 60` | 后两字节的 `u16le` 为记录长度 |
| 奇数条记录之后 | `80` 后两字节的低 12 位为零填充长度，高四位为 `f` |
| 偶数条记录之后 | 两字节的 `u16le >> 4` 为零填充长度，低四位为 `8` |

填充长度字段和 CRC24 之间允许有 `ff` 字节。第一条记录从第 $L$ 字节开始，后续记录的起点由前面记录的长度累加得到。设 $Q$ 为外层 H1 首分配的 Code 5 码字数，$P$ 为零填充长度，则检验的容量关系为

$$L + \sum_i \ell_i + P = 128 Q.$$

例如 480 MS/s 第一帧的 $L=32$，四条记录长 `163、13、386、51` 字节，零填充 `123` 字节。合计 `768` 字节，对应 H1 的 6 个码字。记录跨度保留字节级边界，应用类型和各条记录的独立校验仍待确认。

## 实录和对照

| 输入 | 容量吻合 | 可还原整段 Code 5 分配 | 第二条长度 | 预测位置填充全零 |
|---|---:|---:|---:|---:|
| Qin 档案校准组 | 580/580 | 579/580 | 21 字节 | 580/580 |
| Qin 档案留出组 | 429/429 | 429/429 | 21 字节 | 429/429 |
| 480 MS/s 实测 | 18/18 | 18/18 | 13 字节 | 18/18 |
| 250 MS/s 实测 | 10/10 | 10/10 | 21 字节 | 10/10 |

Qin 的 44 个整组沿用 E077 的冻结划分。250 MS/s 重放和 Qin 档案存在语料重叠，480 MS/s 是另一份独立录波。按冻结的信道接收规则从档案样点新恢复 2,043 个后续码字。每个接受字都通过现有 Code 5 外层校验，接受判据未使用目录语法。档案帧 511 的第三个码字保留为擦除，缺口早于填充区，该帧依然可核对可读的目录、第二条标记及填充。

档案共计 990 帧有非空填充，19 帧长度为零。结合两份宽带，填充内有 536,130 个实收位且全为零。Qin 填充中的另 902 位来自被外层校验支持的擦除恢复。将同长的检验窗向前移两字节，Qin 非空填充只剩 129/990 仍全零，两份原始宽带合计 0/28。这项对照保留了记录末尾本身也可能为零的情况。

每帧预测的第二条起点都读到 `08 5d`。第三条起点以 `01` 或 `02` 开始的比例在 Qin 为 871/896，两份宽带为 28/28。Qin 保留 25 个例外，当前只将这两个值视为常见前缀。记录内部仍可继续做子字段、重复性及独立校验检验。[逐帧结果](../../runs/v098-code5-records-final/artifacts/experiments/E100/results/code5_directory_records.json)

## LEO 频窗

原工程两份 2.5 MS/s 选段的 10 个唯一样点窗、DS7–DS9 的 12 个 7.5 MS/s 频偏档案窗，以及覆盖 26 条标称 25 MS/s 条目的两种频窗均进入投影。7.5 MS/s 使用原规格中冻结的采集频偏和上边缘导频中心，25 MS/s 使用标称调谐。每种输入先将首码字资源映射到可见载波，而后用 GF(2) 上的生成矩阵计算目录目标列的增量秩。[原工程频率约定](https://github.com/misko/leo-tracker-reduxredux/blob/main/docs/concepts/starlink-transmissions.md) · [E099](../../experiments/E099/README.md) · [E071](../../experiments/E071/README.md)

上述频窗没有目录指针字节的直接判决，第二条记录长度的 16 位也无直接判决。即使赋予已知码字起点、扰码和目录指针，未加目录语法先验的理想线性可辨识秩仍为零。E098 在部分 25 MS/s 条件下恢复的是位置不同的时钟位，内层目录不会因此成为可直接读取的字段。[E098](../../experiments/E098/README.md)
